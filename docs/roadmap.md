# OpenSketch 开发路线与插件平台规划

本页是当前产品路线的规划基线。阶段表示交付顺序，不代表功能已经实现；完成状态见[项目完成进度与验收状态](development/2026-11-09-project-status.md)。

## 阶段路线

### M0：模型与可靠性基线

已完成主要原型基础：稳定的文档值模型、坐标和变换规则、编辑事务、原生保存、基础画布、图层树、检查器、文字、撤销/重做和基本导出。

### M1：本地编辑器原型

当前 0.1.0 已基本覆盖：页面与画板、基础图形、选择和变换、容器层级、图层组织、文字编辑、多文档、PNG/PDF 导出和中英文设置。剩余事项以真实 GUI、macOS 15 和大文档验证为主。

### M2：矢量 Alpha 与插件基础

优先实现：

1. 钢笔工具、开放/闭合路径和节点编辑。
2. 路径命中、控制柄、旋转/嵌套/裁剪下的几何一致性。
3. 布尔运算和可恢复的复合路径表示。
4. 渐变、完整描边、基础效果和样式数据扩展。
5. SVG 导出，并逐步加入受支持范围内的 SVG 导入。
6. 插件清单、能力声明、宿主 API、事务边界和内置格式插件的最小实现。

当前进度：路径基础切片、节点编辑、布尔运算、渐变填充、SVG 基础导出和有限 SVG 导入初版已完成。`PathEditing` 已提供路径点规范化、开放/闭合路径、直线追加/插入、直线转贝塞尔曲线、自由/对齐/镜像控制柄、路径闭合切换、反向、节点/贝塞尔控制点移动、单个/多个节点删除和序列校验；`BooleanEditing` 支持闭合矩形、椭圆和路径的并/交/差/排除，并通过图层菜单和检查器命令接入；`LinearGradient` 已接入文档校验、画布/导出渲染和命中测试；SVG 基础导出和有限导入已覆盖常用形状、路径、文字、渐变和描边。插件基础接口仍待样式、复合路径和导出命令边界稳定后冻结。

### M3：UI 设计 Beta 与交付插件

优先实现：

1. 组件实例、共享样式、Stack/约束和响应式布局。
2. JPG、PDF 等格式插件、切片、批量导出和倍率导出。
3. HTML 交互导出插件和素材包插件。
4. MCP/AI 原生操作插件的稳定接口、权限策略和审计记录。
5. 设备同步预览插件的第一个本地设备后端。

### M4：迁移与稳定性

继续评估 Sketch 可编辑导入、自动恢复、大文档优化、错误报告、生产签名和发布安装。多人协作、云端组件库和实时同步另行立项。

## 插件平台总原则

插件不是直接修改 UI 的脚本，而是通过宿主提供的稳定能力访问文档和工作区。第一版平台应先稳定核心模型和事务，再逐步开放扩展点。

### 插件类型

| 类型 | 作用 | 首批交付 |
|---|---|---|
| 格式/导出插件 | 读取、写入或导出设计文档和资源 | 内置 OpenSketch、SVG、PNG；后续 JPG、PDF |
| MCP/AI 操作插件 | 将自然语言或 MCP 工具调用转换为结构化文档操作 | 内置插件，提供预览、确认、事务和撤销 |
| 设备同步预览插件 | 将设计或原型状态同步到设备端 App/显示后端 | 内置协议和首个本地设备后端 |
| HTML 交互插件 | 导出可运行的 HTML/CSS/JS 交互预览 | M3 首批插件 |
| 素材包插件 | 输出图片、字体、颜色、尺寸、布局和代码交付资源 | M3 首批插件 |

### 宿主与插件边界

- 宿主负责文档生命周期、选择、编辑事务、撤销/重做、权限、日志和 UI 生命周期。
- 插件通过版本化的结构化 API 读取文档快照、声明输出、报告进度和返回诊断信息。
- 插件不能绕过事务直接写入内存中的文档；所有文档改变必须经过可预览、可撤销的命令。
- 导出插件默认只读取经过校验的快照，不能修改源文档；必要的导出选项由插件声明并由宿主保存。
- 插件能力必须显式声明，例如 `readDocument`、`writeDocument`、`export`、`network`、`device`、`aiOperation` 和 `fileAccess`。
- 外部插件需要独立标识、版本、兼容的宿主 API 范围和清晰的失败信息；默认不承诺兼容 Sketch 插件运行时。
- 插件输出应支持取消、超时、临时目录隔离和错误恢复，不能因失败破坏源文件或当前编辑状态。

### 插件 UI

插件可以拥有自己的 UI，但 UI 与文档权限、编辑命令和宿主生命周期分离。建议按信任级别提供三种形式：

1. **宿主渲染的配置 UI**：插件通过清单声明文本框、下拉框、开关、倍率、质量和输出范围等参数，宿主使用 SwiftUI/AppKit 渲染。适合 SVG、PNG、JPG、PDF、HTML 和素材包的导出选项，能够自动获得统一的主题、本地化、键盘操作和辅助功能。
2. **插件面板/弹窗**：插件声明一个面板、检查器区域、工具栏按钮或独立窗口，通过版本化 UI 状态和事件协议与宿主通信。适合 AI 对话、设备列表、同步状态、导出进度和降级报告。
3. **插件自有窗口**：外部插件进程可以创建自己的窗口和视图，通过 JSON-RPC 或 XPC 调用宿主 API。适合设备监视器、复杂素材配置和 AI 工作台；窗口可以独立于主编辑器关闭和恢复。

首版不允许普通外部插件把任意 `NSView`/`NSWindow` 注入宿主进程，也不允许 UI 直接持有或修改 `DesignDocument`。这样可以避免插件崩溃、Swift ABI/系统版本差异和未经授权的文档修改影响主应用。受信任的内置插件以后可以使用原生 SwiftUI/AppKit 控件，但仍必须通过同一套命令和权限 API。

插件 UI 的事件流应类似：

```text
插件清单声明 UI
    ↓
宿主创建面板或窗口
    ↓
插件发送 UI 状态 / 宿主发送用户事件
    ↓
插件请求查询、预览、导出或文档命令
    ↓
宿主校验权限并提交事务
```

UI 能力单独写入插件清单，例如 `panel`、`configurationUI`、`standaloneWindow`、`toolbarItem`；它不等同于 `writeDocument`、`network` 或 `device` 权限。关闭窗口、取消操作、插件退出和宿主退出都必须有明确的生命周期事件，未提交的操作不得改变文档。

首批 UI 使用场景：

- 格式插件：导出范围、倍率、质量、背景和输出目录设置。
- MCP/AI 插件：上下文选择、操作计划、差异预览、确认、撤销和操作日志。
- 设备同步插件：设备发现、连接状态、设备尺寸、主题、同步进度和演示控制。
- HTML/素材包插件：交互选项、资源格式、设计令牌、字体和降级报告。

正式实现时需要为 UI 状态、事件、焦点、取消、错误、本地化、暗色模式、动态字体和辅助功能增加契约测试。插件 UI 不应成为绕过宿主权限和事务边界的通道。

## 2.1 格式与导出插件

### 初始内置插件

第一版插件化导出保留现有能力，并将其迁移到统一接口：

- **OpenSketch 格式插件**：内置、可读写，是当前 `.opensketch` 的默认持久化格式。由于文档生命周期依赖它，宿主必须始终提供此插件或等价内置实现。
- **SVG 导出插件**：内置，优先覆盖路径、形状、文字、填充、描边、透明度和常见变换；不支持的特性必须报告降级。
- **PNG 导出插件**：内置，支持当前页面、选择、画板和倍率输出，复用现有渲染快照与超大图像保护。

### 后续格式插件

- JPG：在栅格导出公共能力稳定后提供质量、背景色和色彩空间选项。
- PDF：将现有 PDF 导出迁移到插件接口，保留矢量输出和页面尺寸语义。
- 后续格式可以由独立插件加入，但不得改变核心文档模型或静默修改源文件。

### 统一接口方向

```text
FormatPlugin
  manifest() -> PluginManifest
  capabilities() -> FormatCapabilities
  inspect(documentSnapshot, options) -> ExportPlan
  export(documentSnapshot, options, destination, progress) -> ExportResult
```

OpenSketch 的保存/打开还需要 `decode`、`encode` 和格式迁移能力；普通导出插件只需声明输入快照、选项、输出类型和诊断信息。正式 API 需在 M2 设计阶段冻结，并配套格式、像素、取消、失败不改源文档和版本兼容测试。

## 2.2 MCP 与 AI 原生操作插件

MCP 和 AI 能力作为内置插件接入同一套命令系统，不通过模拟鼠标键盘实现。目标是让 AI 能够理解文档结构、提出可审阅变更并安全执行。

### 第一版能力

- 查询文档、页面、图层、几何、样式、文本和当前选择。
- 创建、修改、移动、重排、编组、命名、删除和导出对象。
- 运行对齐、分布、布局和格式转换等可组合命令。
- 先生成结构化操作计划和差异预览，再由用户确认提交。
- 每次批量操作进入一个明确的编辑事务，可整体撤销；失败时回滚整个事务。
- 将不支持的能力、冲突、锁定对象、格式降级和权限拒绝作为结构化结果返回。

### 安全与可控性

- 只允许调用已注册的命令和插件能力，不暴露任意 Swift、文件系统或进程执行入口。
- 读取、文档修改、导出、网络访问和设备连接分开授权。
- 默认使用当前文档的受限上下文；跨文档、覆盖源文件、写入外部目录和联网必须明确授权。
- 保留操作来源、参数、时间、结果和回滚信息，供审计和问题复现。
- AI 生成的文本、代码和导出文件均视为普通插件输出，不能绕过文档验证和用户确认。

### MCP 适配层方向

MCP 工具应映射到稳定的 OpenSketch 命令/查询接口，而不是直接依赖 SwiftUI 或 AppKit 类型。未来可提供本地 MCP server、受限远程连接和编辑器内的 AI 面板；传输方式、认证和远程部署不在第一版本地插件范围内。

## 2.3 设备同步预览插件

设备同步预览用于把画板、原型状态或 HTML 交互预览发送到设备端运行的 App 或显示后端，实现设计、演示和设备尺寸验证。

### 目标能力

- 发现和配对本地设备或设备端预览 App。
- 选择页面、画板、原型入口或当前选区进行预览。
- 增量同步文档快照、资源和交互状态，避免每次完整导出。
- 预览设备尺寸、像素密度、方向、主题和输入事件。
- 支持断开重连、同步状态、版本不匹配提示和只读演示模式。
- 设备端可作为独立 App 或实现公开协议的显示后端，不要求设备运行完整 OpenSketch。

### 边界与阶段

第一版只支持明确注册的本地后端和用户主动发起的连接，不默认开放局域网广播或远程控制。宿主负责权限和连接生命周期，设备插件负责协议适配、资源传输和设备能力声明。后续再评估远程设备、多人演示和输入回传。

## 2.4 HTML 交互与素材包插件

### HTML 交互插件

输出一个可独立打开的 HTML 包，包括：

- HTML/CSS/JS 和资源目录。
- 页面、画板、热点、链接、滚动区域和基础转场。
- 设备尺寸和响应式预览配置。
- 对不支持的组件、字体、效果和交互给出导出报告。
- 离线运行优先，不默认上传设计文件或依赖外部服务。

HTML 插件第一阶段只覆盖明确声明的交互模型；不把任意 SwiftUI/AppKit 行为或编辑器内部状态直接序列化成网页代码。

### 素材包插件

输出供开发交付使用的目录或压缩包，包括：

- PNG、SVG、JPG 等已选择倍率和格式的图片资源。
- 字体引用、颜色、字号、间距、圆角和尺寸变量。
- 页面/画板/图层清单、命名和层级信息。
- 可选的 JSON 设计令牌、CSS 变量和资源索引。
- 资源来源、缺失字体、重复文件名和降级信息。

素材包插件与 HTML 插件共享导出快照和资源解析器，但输出目标、选项和验收报告保持独立。

## 交付顺序与退出条件

### P0：插件基础设计（M2 前置）

- 冻结插件清单、能力声明、宿主 API 版本和错误模型。
- 明确文档快照、导出选项、进度、取消和诊断结构。
- 将现有 OpenSketch/PNG/PDF 导出抽出适配层，先不改变用户行为。
- 为插件操作建立事务、权限和日志测试。

### P1：内置格式插件与 SVG（M2）

- 内置 OpenSketch、SVG、PNG 插件通过统一接口工作。
- SVG 路径、样式、文字、变换和降级报告有固定回归样例。
- 导出失败、取消、超大输出和源文档保护通过验收。

### P2：MCP/AI 原生操作（M2–M3）

- 查询和编辑命令可从 MCP 调用。
- 计划预览、用户确认、单事务撤销、权限拒绝和审计记录完整。
- AI 操作不依赖 UI 自动化，且与人工编辑共享同一命令实现。

### P3：设备预览与 HTML/素材包（M3）

- 至少一个设备端 App/显示后端完成配对、同步、重连和只读演示。
- HTML 离线包可打开并运行声明支持的交互。
- 素材包可复现导出资源、设计令牌和缺失/降级报告。

### P4：外部插件生态（M3–M4）

- 插件安装、版本兼容、禁用、卸载和故障隔离。
- 明确代码签名、沙箱、网络、设备和文件权限策略。
- 提供插件开发文档、示例插件、契约测试和可复现打包流程。

## 相关验收门槛

插件平台进入稳定开发前，需要满足：

1. 文档 UUID、层级、变换、样式、文字和资源引用在快照中可稳定表达。
2. 插件操作可以被事务化、撤销、取消和重放。
3. 导出插件不会修改源文档，失败不会覆盖已有有效文件。
4. AI/MCP 操作与人工菜单使用同一套核心命令和验证规则。
5. 设备、HTML 和素材包输出都能报告不支持特性，而不是静默丢失。
6. 插件版本、能力、权限和错误均有自动化契约测试。
